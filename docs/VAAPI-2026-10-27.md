# 浏览器硬件解码打通记录（VA-API / qcom-iris）— 2026-10-27

## 结论

在本机（Xiaomi Pad 6 Pro / liuqin / SM8475，Ubuntu 26.04，内核 6.17.0-rc1-gfe81794b5e1b）上，
**VA-API 硬件解码已经可用**：

```
$ vainfo --display drm --device /dev/dri/renderD128
vainfo: Driver version: Iris V4L2 stateful VA-API backend
      VAProfileH264ConstrainedBaseline: VAEntrypointVLD
      VAProfileH264Main               : VAEntrypointVLD
      VAProfileH264High               : VAEntrypointVLD
      VAProfileHEVCMain               : VAEntrypointVLD
      VAProfileHEVCMain10             : VAEntrypointVLD
      VAProfileVP9Profile0            : VAEntrypointVLD
      VAProfileVP9Profile2            : VAEntrypointVLD
```

ffmpeg 实测：

```
Selecting decoder 'h264' because of requested hwaccel method vaapi
VAAPI driver: Iris V4L2 stateful VA-API backend
→ 23 frames decoded; 0 decode errors   （退出码 0）
```

**没有打任何内核补丁**。`radxa-pkg/qcom-va-driver` 仓库 `patches/` 里那 5 个 iris 补丁
（decode-order output、更大的 capture 池、去块滤波控件、错误时间戳、NOSHOW 回收）对基础
H.264 解码不是必需的，属于 4K/B 帧/AV1 等场景的增强。

## 用的什么

[`radxa-pkg/qcom-va-driver`](https://github.com/radxa-pkg/qcom-va-driver)（原名 `libva-v4l2`）：
实验性的 Qualcomm Iris VA-API 后端，走 **V4L2 stateful M2M** 接口。
上游声明支持 H.264（Baseline/Main/High 8bit）、HEVC（Main/Main10）、VP9、AV1，
并在 SC8280XP / X1E80100 上跟 FFmpeg、GStreamer、mpv、VLC、Chromium、Kodi 对过。

> 注意：`mxsrc/libva-v4l2` 是**另一条线**（stateless Request API），README 明确写"stateful 支持
> 是未来工作"，不能用在本机。真正对应本机 iris（stateful）的是 `radxa-pkg/qcom-va-driver`。

## 构建与安装（本机实测步骤）

```sh
# 1) 依赖（设备上原本没有编译工具链）
sudo apt-get install -y build-essential meson ninja-build pkg-config \
     libva-dev libdrm-dev libegl-dev libgles-dev libgbm-dev git vainfo

# 2) 源码
git clone --depth 1 https://github.com/radxa-pkg/qcom-va-driver /root/qcom-va-driver
cd /root/qcom-va-driver

# 3) 配置（关掉 CDSP VPP：它需要 ARM64 构建机 + GHC，先用不到）
meson setup build --buildtype=release --prefix=/usr -Dlibdir=lib -Dcdsp_vpp=disabled
ninja -C build
sudo meson install -C build
# → 安装到 /usr/lib/dri/v4l2_drv_video.so，并自动建 msm_drv_video.so 别名
```

**关键补充**：libva 在 Debian/Ubuntu arm64 上的默认驱动目录是
`/usr/lib/aarch64-linux-gnu/dri/`，而 `-Dlibdir=lib` 会装到 `/usr/lib/dri/`。
所以必须再复制一次（否则 `vainfo` 找不到）：

```sh
sudo cp -f /usr/lib/dri/v4l2_drv_video.so /usr/lib/aarch64-linux-gnu/dri/
sudo ln -sfn v4l2_drv_video.so /usr/lib/aarch64-linux-gnu/dri/msm_drv_video.so
```

有了 `msm_drv_video.so` 这个别名，应用**不需要设置 `LIBVA_DRIVER_NAME`** 就会自动选中
（libva 按显卡驱动名 `msm` 匹配）。

## 验证

```sh
vainfo --display drm --device /dev/dri/renderD128
ffmpeg -hwaccel vaapi -hwaccel_device /dev/dri/renderD128 -i input.mp4 -f null -
mpv --hwdec=vaapi input.mp4      # 需要 mpv 支持 vaapi（本机 mpv 0.41 可以）
```

## 浏览器还差一步

snap 版 Firefox 的沙箱里：

```
/dev/dri/renderD128       可见 ✓
/usr/lib/aarch64-linux-gnu/dri/   不可见 ✗ （VA 驱动 .so 在宿主机上）
```

所以 snap Firefox 加载不到驱动。解法：改用 **Mozilla 官方 arm64 包**（tar 解到 `/opt/firefox`，
不动 snap，可随时删除），或者把 `/usr/lib` 通过 snap 的 `classic` 模式暴露出来。
这一步尚未完成（下载在设备上受网络限制）。

## 回滚

```sh
sudo rm -f /usr/lib/dri/v4l2_drv_video.so /usr/lib/dri/msm_drv_video.so
sudo rm -f /usr/lib/aarch64-linux-gnu/dri/v4l2_drv_video.so \
           /usr/lib/aarch64-linux-gnu/dri/msm_drv_video.so
# 之后 vainfo 会退回"找不到 VA 驱动"，与安装前一致
```
